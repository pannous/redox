## Summary

### ipcd Investigation Complete

**Root Cause Identified:**
ipcd crashes during `fork()` because `has_proc_fd` is false in the Cranelift-compiled relibc. This is a compile-time flag that isn't being enabled properly for the Cranelift target.

**Workaround Attempted:**
Modified `daemon/src/lib.rs` to skip fork() entirely and run daemons in foreground mode.

**New Blocker:**
When rebuilding ipcd with the modified daemon, the binary crashes during CRT initialization - even before reaching main(). The crash occurs at `relibc_start_v1` with:
- Valid entry point (0x35AE70)
- Exception during memory access at 0x3A8378

**Key Fixes Found:**
1. CRT objects must combine BOTH `.o` and `.asm.o` files using `ld.lld -r`
2. relibc dependencies must all use `redox_syscall = "0.6.0"` (not 0.7.0)
3. Pin `redox_event = "=0.4.2"` exactly

**Likely Cause of Remaining Crash:**
ABI mismatch between Cranelift-compiled ipcd and LLVM-compiled components in the ISO's runtime.

**Next Steps to Fully Fix:**
1. Rebuild the entire ISO with Cranelift-compiled userspace
2. Or investigate the specific CRT initialization incompatibility
3. Consider testing with the official Redox cross-compiler

All findings have been documented in `/opt/other/redox/.claude/CLAUDE.md`.
