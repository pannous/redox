## Fixed: virtio-netd crash on large downloads

The crash has been fixed. The issue was in `virtio-core/src/transport.rs`:

**Root Cause:** When sending network packets, the TX descriptors were never being recycled because `write_packet()` dropped the `PendingRequest` future without polling it. Eventually all descriptors were exhausted, and `send()` would panic on `descriptor_stack.pop().unwrap()`.

**Solution:**
1. Added `reclaim_completed()` method that scans the used ring and recycles completed TX descriptors
2. Changed `Queue::send()` to return `Option<PendingRequest>` instead of panicking
3. `send()` now calls `reclaim_completed()` before checking availability
4. Updated all virtio drivers (netd, blkd, gpud, 9pd) to handle the new return type

- `drivers/virtio-core/src/transport.rs:192-246` - Core fix
- `drivers/net/virtio-netd/src/scheme.rs` - Returns EWOULDBLOCK if queue full
