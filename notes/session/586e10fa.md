## 🤖 Assistant

No. The ISO is the **backing file** (read-only base), while the qcow2 stores all changes/snapshots on top of it. They're separate:

- `pure-rust.iso` - unchanged base image
- `dev.qcow2` - contains only the delta (your changes + snapshots)

To backup the current state including snapshots:

```bash
# Option 1: Copy the qcow2 (still depends on ISO)
cp build/aarch64/dev.qcow2 build/aarch64/dev.qcow2.bak

# Option 2: Flatten into standalone image (no ISO dependency)
qemu-img convert -O qcow2 build/aarch64/dev.qcow2 build/aarch64/standalone-backup.qcow2
```

Option 2 merges the ISO + all qcow2 changes into one self-contained file. That's a true portable backup.

## 👤 Human

can I tell build/aarch64/dev.qcow2 (.bak) to Use a copy of the original pure-rust.iso. The problem is that the ISO can only be used by one QEMU process, and I often want to have my own shell while you are debugging.

---

## 🤖 Assistant

Yes, use `qemu-img rebase` to point a qcow2 at a different backing file:

```bash
# Create a copy of the ISO for parallel use
cp build/aarch64/pure-rust.iso build/aarch64/pure-rust-debug.iso

# Rebase the backup qcow2 to use the copy
qemu-img rebase -u -b pure-rust-debug.iso -F raw build/aarch64/dev.qcow2.bak
```

The `-u` flag does an unsafe (fast) rebase - it just updates the pointer without checking content. This works because the ISO copies are identical.

Now you can run both simultaneously:
- `dev.qcow2` → `pure-rust.iso` (your shell)
- `dev.qcow2.bak` → `pure-rust-debug.iso` (my debugging)

Or create a fresh qcow2 pointing at the copy:
```bash
qemu-img create -f qcow2 -b pure-rust-debug.iso -F raw build/aarch64/debug.qcow2
```
