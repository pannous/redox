# Linux-Style Identity Mapping for AP Boot

## Problem Summary

APs fail to boot due to physical-to-virtual address transition issues. When APs jump from identity-mapped physical space (~0x8e0f_xxxx) to KERNEL_OFFSET virtual space (~0xFFFF_FF00_xxxx_xxxx), they experience silent instruction fetch failures.

**Evidence**: Markers show `ABCDEFGSTJK` (assembly works) but never `!RUST` (Rust code never runs). Multiple approaches tried (PC-relative, BL, PHYS_OFFSET calculation) all failed.

## Solution: Linux-Style Identity Mapping

Implement the proven Linux kernel approach for secondary CPU boot:

1. Create `.idmap.text` section for transition code (≤4KB)
2. Create separate identity page table (like Linux's `idmap_pg_dir`)
3. Use dual page tables: TTBR0=identity, TTBR1=kernel
4. Enable MMU while executing from identity-mapped code
5. Jump to virtual space after MMU is active

**Key Insight**: Linux keeps MMU setup code in identity-mapped space and uses dual page tables to enable a smooth transition.

```rust
/// Create identity-mapped page table for AP boot transition
/// Like Linux's idmap_pg_dir - maps only .idmap.text section
unsafe fn create_idmap_pg_dir(
    bump_allocator: &mut BumpAllocator,
    mapper: &mut PageMapper<KernelMapper>,
) -> PhysicalAddress {
    extern "C" {
        static __idmap_text_start: u8;
        static __idmap_text_end: u8;
    }

    let idmap_start = &__idmap_text_start as *const u8 as usize;
    let idmap_end = &__idmap_text_end as *const u8 as usize;
    let idmap_size = idmap_end - idmap_start;

    info!("Creating idmap_pg_dir: 0x{:x}-0x{:x} ({} bytes)",
          idmap_start, idmap_end, idmap_size);

    // Get kernel physical base
    let kernel_phys_base = kernel_phys_base();

    // Calculate physical address of .idmap.text section
    let idmap_phys_start = idmap_start - KERNEL_OFFSET + kernel_phys_base;

    // Create separate page table for identity mapping
    let idmap_table = PageMapper::create(TableKind::Kernel, bump_allocator)
        .expect("failed to create idmap page table");

    // Map .idmap.text 1:1 (physical = virtual)
    let pages = (idmap_size + PAGE_SIZE - 1) / PAGE_SIZE;
    for i in 0..pages {
        let phys = PhysicalAddress::new(idmap_phys_start + i * PAGE_SIZE);
        let virt = VirtualAddress::new(idmap_phys_start + i * PAGE_SIZE);

        // Executable, kernel-only, cached
        let flags = page_flags_from_elf_flags::<Arch>(
            xmas_elf::program::PF_X.bits() | xmas_elf::program::PF_R.bits()
        );

        idmap_table.map_phys(virt, phys, flags)
            .expect("failed to map idmap page");
    }

    idmap_table.table().phys()
}
```

**Purpose**: Creates a minimal page table that only maps the transition code 1:1.

## Why This Works

1. **Identity mapping for transition code**: `.idmap.text` section is mapped 1:1 at its physical address

4. **Seamless transition**: After MMU enable, can jump to virtual addresses because both mappings exist
5. **Matches Linux proven approach**: Same architecture used by Linux kernel for secondary CPU boot
