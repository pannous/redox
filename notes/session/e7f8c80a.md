=== Testing: HVF + no virtualization ext ===
Options: -M virt,virtualization=off -accel hvf -cpu host    What does the virtualization parameter mean here?

---

## 🤖 Assistant

The `virtualization=off` parameter in `-M virt,virtualization=off` controls whether the **guest VM sees virtualization extensions** (EL2/hypervisor support) in its virtual CPU.

**What it does:**
- `virtualization=on` (default with `-cpu host`): Exposes ARMv8 virtualization extensions (VHE, EL2) to the guest OS, allowing nested virtualization
- `virtualization=off`: Hides these extensions - the guest only sees EL0/EL1 (user/kernel mode)

**Why this matters for Redox:**
Given your HVF crash issues noted in CLAUDE.md, this is an interesting test because:

1. **Simpler CPU model**: Without virtualization extensions, the emulated CPU is simpler - fewer corner cases in exception handling
2. **EL2 traps**: HVF on Apple Silicon uses EL2 to trap guest operations. If Redox's kernel accidentally touches EL2-related registers, `virtualization=off` might prevent those code paths from triggering

**However**, this probably won't fix your "Lacks grant" crashes because those are likely related to:
- Memory mapping/grant table handling in userspace
- Page table or TLB interactions with HVF
- Not EL2/virtualization extension issues

The proven workaround from your notes is `-cpu cortex-a72` (full emulation, no HVF), which avoids all HVF edge cases at the cost of speed.
