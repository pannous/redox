## Root Cause

**Per-file transaction overhead** in `redoxfs/src/mount/redox/scheme.rs:827`:
```rust
fn fstat(&mut self, id: usize, stat: &mut Stat, ...) {
    self.fs.tx(|tx| file.stat(stat, tx))  // NEW transaction per stat!
}
```

Each transaction does:
1. **5-level tree walk** (l3→l2→l1→l0→data)
2. **Decrypt each block** even on cache hit
3. **Hash verification** per block
4. **Transaction setup/commit** overhead

## Cost Breakdown (~115ms per stat)

| Component | Time |
|-----------|------|
| Transaction create/commit | ~5-10ms |
| 5× read_block with crypto | ~50-70ms |
| Hash verification | ~10-20ms |
| Virtio-blk latency | ~20-30ms |

## Why No Caching Helps

- **DiskCache exists** (16MB) but only caches raw encrypted blocks
- **No decrypted block cache** - crypto runs every time
- **No node metadata cache** - tree walk repeats for every file
- **Transaction isolation** - each stat is independent

## Solution Options

1. **Node metadata cache** - cache stat results across transactions
2. **Batch transactions** - reuse transaction for directory listings  
3. **Decrypted block cache** - avoid re-decrypting same blocks
4. **Readdir+stat combo** - return metadata during directory read

# Plan: Lightweight Read-Only Context for stat() Optimization

## Problem
Each stat() cache miss creates a full `Transaction` which:
- Clones the allocator (`Vec<BTreeSet<u64>>`) - expensive
- Copies the 4KB header
- Creates empty collections
- Runs commit/sync even for read-only operations

Current: ~47ms per stat (cache miss)
Target: Significantly reduce by eliminating transaction overhead

## Solution: ReadOnlyContext

Create a lightweight read-only context that bypasses transaction machinery entirely.

### Key Insight
`read_block()` checks `write_cache` for pending writes, but read-only operations never have pending writes. We can create a simpler path that:
- Takes `&FileSystem` (immutable borrow) instead of `&mut FileSystem`
- No allocator clone needed
- No header copy needed
- No commit needed

## Implementation

### Step 1: Add ReadOnlyContext to transaction.rs

```rust
/// Lightweight read-only context - no allocator clone, no commit
pub struct ReadOnlyContext<'a, D: Disk> {
    pub(crate) fs: &'a FileSystem<D>,
}

impl<'a, D: Disk> ReadOnlyContext<'a, D> {
    pub fn new(fs: &'a FileSystem<D>) -> Self {
        Self { fs }
    }

    /// Read a block directly from disk (no write cache)
    pub unsafe fn read_block<T: BlockTrait>(&self, ptr: BlockPtr<T>) -> Result<BlockData<T>>

    /// Read a tree node (5-block walk)
    pub fn read_tree<T: BlockTrait>(&self, ptr: TreePtr<T>) -> Result<TreeData<T>>
}
```

### Step 2: Add read_only() method to FileSystem

```rust
impl<D: Disk> FileSystem<D> {
    /// Execute a read-only operation without transaction overhead
    pub fn read_only<F, T>(&self, f: F) -> Result<T>
    where
        F: FnOnce(&ReadOnlyContext<D>) -> Result<T>,
    {
        let ctx = ReadOnlyContext::new(self);
        f(&ctx)
    }
}
```

### Step 3: Update fstat() in scheme.rs

Change cache-miss path from:
```rust
self.fs.tx(|tx| file.stat(stat, tx))?;
```

To:
```rust
self.fs.read_only(|ctx| file.stat_readonly(stat, ctx))?;
```

### Step 4: Add stat_readonly() to Resource trait
