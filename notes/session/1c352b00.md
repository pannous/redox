## Summary

I investigated the sysroot issue for rustc on Redox. Here's what we found:

### What Works on Redox
- `rustc --version` ✓
- `rustc --help` ✓  
- `rustc --print sysroot` ✓
- `rustc --print target-list` ✓
- `rustc --print target-libdir` ✓ (default target only)

### What Crashes
- Any compilation operation (`rustc file.rs`)
- Using custom target JSON (`--target /path/to/spec.json`)

### Root Cause: SVH Version Mismatch

The cross-compiled rustc reports version **1.86.0-dev** (from `CFG_RELEASE`), but the host nightly that builds the sysroot rlibs is **1.94.0-nightly**.

When rustc tries to load rlibs, it computes an expected SVH (Stable Version Hash) based on its own internal configuration. The rlibs have SVH computed by a different compiler, so they don't match.

### Sysroot Location
Created at `/opt/other/redox/share/sysroot/` with:
- `lib/rustlib/aarch64-unknown-redox/lib/` - 17 rlibs from host `-Z build-std`
- `lib/rustlib/aarch64-unknown-redox-clif/lib/` - 225 rlibs from rustc deps

### Recommended Fix
**Rebuild rustc with matching version string**:
```bash
# In build-rustc-core.sh, change:
export CFG_RELEASE="1.94.0-nightly"
export CFG_VERSION="1.94.0-nightly"
```

This would align the SVH expectations, allowing rustc to load rlibs built by the same-version host nightly. This requires a full rustc rebuild (~hours).

The notes have been updated at `/opt/other/redox/notes/rustc-on-redox.md` and committed.
