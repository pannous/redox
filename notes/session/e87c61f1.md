## Summary

**Fixed the black display issue on Redox OS with QEMU aarch64 ramfb.**

### Root Cause
The framebuffer was mapped with `WriteCombining` memory type, but the kernel only implements WriteCombining for x86/x86_64. On aarch64, it fell through to default cached memory, causing CPU writes to go to cache instead of RAM. Since QEMU's ramfb reads directly from RAM, it never saw the pixel data.

### The Fix
1. **Use `DeviceMemory` instead of `WriteCombining` on aarch64** - properly maps the framebuffer as device memory with correct page table attributes
2. **Add `DSB SY` barrier after framebuffer writes** - ensures writes to device memory are visible to external devices

- `recipes/core/base/source/drivers/graphics/vesad/src/scheme.rs` - conditional memory type + DSB barrier
