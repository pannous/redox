## 🤖 Assistant

The crash has been fixed. Here's a summary:

## Problem
When running `VT=3 orbital orblogin launcher`, the system crashed with a kernel exception in `/usr/bin/inputd`. The crash was caused by `orblogin` calling `inputd --keymaps` during initialization, but `inputd` only handled the `-A` argument for VT activation - any other argument caused a panic.

## Solution
Added stub handlers to `inputd` for the keymap-related arguments:
- `--keymaps`: Returns "us" as the only available keymap
- `-K <keymap>`: Accepts the argument but ignores it (actual keymap handling is done by `ps2d`, not `inputd`)

## Testing
With `PATH=/scheme/9p.hostshare:$PATH` set before running orbital, both `orbital` and `orblogin` start successfully without crashing.

## Commits
1. `fix(inputd): Add stub handlers for --keymaps and -K arguments`
2. `docs: Document inputd keymap crash fix`

## Note
Due to QEMU's `snapshot=on` mode, the `/usr/bin/inputd` on the running disk image isn't updated. To use the fixed inputd, either:
1. Set `PATH=/scheme/9p.hostshare:$PATH` before running orbital
2. Rebuild the full disk image without snapshot mode
3. Add a startup script that copies the updated inputd from the 9p share
