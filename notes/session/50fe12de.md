### Linux Kernel Approach (Working Implementation)

**Physical-to-Virtual Transition Method:**
1. Secondary CPUs enter at **physical address** via PSCI `CPU_ON`
2. Entry point: `secondary_entry` → `secondary_startup` (in `.idmap.text` section)
3. **Dual page tables** loaded before MMU enable:
   - `TTBR0_EL1` = `idmap_pg_dir` (identity mapping for boot code)

4. MMU enabled **while still executing from identity-mapped code**
5. PC-relative load: `ldr x8, =__secondary_switched` (virtual address)
6. Jump: `br x8` transitions to high virtual space
7. Continue execution at `__secondary_switched` in virtual space

**Key Insight**: Linux maintains a separate **identity-mapped page table** (`idmap_pg_dir`) specifically for MMU transition code (max 4KB, in `.idmap.text` section).

## SELECTED APPROACH: Option 1 - Identity-Mapped Address Test

### Strategy

The kernel is **triple-mapped** in virtual memory:
1. **KERNEL_OFFSET** (`0xFFFF_FF00_xxxx_xxxx`) - High virtual addresses (FAILING)
2. **PHYS_OFFSET** (`0xFFFF_8000_xxxx_xxxx`) - Direct physical mapping  
3. **Identity** (`0x8e0f_xxxx`) - Physical addresses mapped 1:1 (WORKING for assembly)

**Current Problem**: Jumping from identity space to KERNEL_OFFSET addresses fails with silent instruction fetch failure.

**Solution**: Use **PC-relative addressing** to jump to the **identity-mapped** address of `ap_entry_minimal` instead of the KERNEL_OFFSET address.

### Implementation

**File**: `recipes/core/kernel/source/src/arch/aarch64/start.rs`

**Lines to modify**: ~488-563 (assembly block in `kstart_ap`)

**Current code** (lines ~488-557):
```asm
// Load the high virtual address using ADR + data word
adr x8, start_addr
ldr x8, [x8]           // x8 = 0xFFFF_FF00_0000_xxxx (KERNEL_OFFSET)
// ... diagnostic hex printing ...

    .quad {ap_entry}    // Resolves to KERNEL_OFFSET address
```

**New code**:
```asm
// Use PC-relative addressing to get identity-mapped address
// PC is at ~0x8e0fxxxx (identity space), so adrp/add gives identity address

// Marker 'P' for PC-relative
mov x9, #0x09000000
mov w11, #0x50  // 'P'
str w11, [x9]

// Get identity address using PC-relative instructions
adrp x8, {ap_entry}
add x8, x8, :lo12:{ap_entry}

// Marker 'I' for Identity address loaded
mov w11, #0x49  // 'I'
str w11, [x9]

// Flush instruction cache
ic iallu
dsb ish
isb

// Marker '>' before jump
mov w11, #0x3E  // '>'
str w11, [x9]

// Jump to identity-mapped address
br x8

// Marker 'X' if jump fails (should not reach)
mov w11, #0x58  // 'X'
str w11, [x9]

// Remove start_addr data word - no longer needed
```

**Keep the rest**: Assembly function end, `ap_entry = sym ap_entry_minimal`, etc.

### Why This Works

1. **PC-relative addressing**: `adrp x8, {ap_entry}` calculates address relative to current PC
2. **Current PC in identity space**: Assembly executes at `~0x8e0f_xxxx`
3. **Result is identity address**: `x8 = ~0x8e0f_xxxx` (identity-mapped `ap_entry_minimal`)
4. **Identity mapping proven to work**: All assembly markers (ABCDEFGSTJK) succeed
5. **Execute permission exists**: Identity mapping already allows instruction fetch
